## How each check was made, and how sure it is

- Domains: each name was looked up in the registry's own RDAP service (chosen from the IANA bootstrap file; port-43 WHOIS for registries without RDAP such as .co) and cross-checked against DNS delegation with two public resolvers. 'Available' is reported only when the registry says the name is not registered AND DNS has no delegation for it; disagreement is reported as couldn't confirm.
- X (Twitter): the public profile page x.com/<handle> is fetched anonymously. An existing account returns the profile (title '<name> (@handle) / X'); a free handle returns X's 404 'User Profile Not Found' page. Suspended or protected accounts can also show the 404 page, so 'available' on X means 'no public profile' — a rate-limit or challenge page is reported as couldn't confirm. Verified in the same run with a random control handle and X's own @x account.
- Instagram has no public availability API. The exact profile URL instagram.com/<handle>/ is fetched anonymously with a link-preview crawler user agent (the only way Instagram serves profile metadata without a login): a profile with og:type=profile means taken; Instagram's bare shell with no profile metadata means no public account. A login wall, rate limit ('please wait a few minutes') or challenge is reported as couldn't confirm — never guessed. Each run re-verifies the method with a random control handle (must read available) and Instagram's own @instagram (must read taken).
- TikTok has no public availability API. The exact profile URL tiktok.com/@<handle> is fetched anonymously; because TikTok is not reachable from the checker's own network it is read through a third-party page reader (r.jina.ai). A profile title '<name> (@handle) | TikTok' means taken; TikTok's 'Couldn't find this account' page means available; a captcha, redirect or timeout is couldn't confirm. Each run re-verifies the method with a random control handle and @tiktok.
- GitHub: the public REST API api.github.com/users/<handle> (200 taken, 404 available), falling back to the profile page when the API rate limit is hit; organisations count as taken.
- App stores: Apple App Store via the public iTunes Search API (exact-name matches plus close variants are listed); Google Play via its public search page (parsed from HTML; reported as couldn't confirm when the page cannot be read).
- Trademarks: USPTO (United States), EUIPO (European Union) were searched in these public registers: USPTO trademark search (tmsearch.uspto.gov); EUIPO eSearch plus. The USPTO is searched in the USPTO's own trademark search backend (tmsearch.uspto.gov), the EUIPO in EUIPO eSearch plus, and the UK IPO and WIPO Madrid registers through TMview (the EUIPO/TMDN federated search; TMview is also the fallback when a national search is down). Each search asks for marks containing the name (the USPTO search also fuzzy-matches); a hit is listed as 'identical' when its text equals the name and 'similar' when the name is a whole word of the mark, the mark is the name plus a short suffix, or the mark is one typo away (two for names of 10+ characters). Each row carries the application/registration number, status, owner, Nice classes and a link to the official record. Marks that are only phonetically or visually close are not detected: that is an attorney's search.
- Certainty: 'Taken' and 'Available' are reported only on a positive signal from the source named; everything else (login walls, rate limits, challenge pages, timeouts, registries that did not answer) is 'Couldn't confirm'.
